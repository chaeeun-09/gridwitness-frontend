# GridWitness Frontend

전력 고장파형 분석 지원 시스템 GridWitness의 웹 화면 (React + TypeScript + Recharts + three.js).
백엔드 없이 브라우저 안의 **목 데이터**로만 동작합니다 (사건은 localStorage에 저장).

```bash
npm install
npm run dev          # http://localhost:5173
```

## 화면

| 메뉴 | 경로 | 내용 |
|---|---|---|
| 대시보드 | `/` | 장치 연결 상태, 총 전압·전류(실제/예상), 이상 탐지 요약, AI 모델 2종, 사건 현황 |
| 스마트 마을 | `/village` | 3D 마을(주택 3 + 가로등 2), 정전 발생/전력 복구(릴레이), 전체 전압·전류·전력, **지하 배선 보기**(위에서 본 바닥판 내부 · 핀 단위 배선 · 부품 클릭 확대·핀 연결 패널 · 선 hover 연결 정보), 낮/밤, 고장 시뮬레이션 |
| 실시간 분석 | `/live` | 예상 전류 vs 실제 전류, 이상 점수(주의 0.3 / 이상 0.6), 채널별 잔차, 경고 이력 |
| 고장파형 분석 | `/cases`, `/cases/new`, `/cases/:id` | CSV·**COMTRADE(.cfg+.dat, ASCII/BINARY)** 업로드 → 7채널 입력 검사 → AI 4종 분류/보류 → 3D·2D 파형 → 사람 검토. 입력 예시 시나리오 15종 |
| 공공데이터 분석 | `/public-data` | 한전 지역·시간대별 전력사용량 패턴, CSV 가져오기·점검, 패턴을 마을 부하 시나리오로 재생 |
| 사건·검토 이력 | `/history`, `/history/:id` | IoT 이상 이벤트 / 고장파형 사건을 유형별로 구분 |
| 설정 | `/settings` | 데이터 출처(Mock / 실측 Arduino), 회로 구성(부품·배선), AI 모델, 작업자, 데이터 초기화 |

## 데이터와 AI 분리

세 데이터는 단위·측정 주기·설비 규모·목적이 달라 하나의 모델에 함께 학습시키지 않습니다.

| 데이터 | 분석 대상 | 사용처 |
|---|---|---|
| Arduino + INA219 ×1 (Mock 또는 실측) | 모형 전체의 5V DC 전압·전류 | **IoT 이상 탐지** — `src/lib/village.ts` `anomalyScore()` |
| 공개 고장파형 (Xiong et al.) | 교류 고장 이벤트 7채널 | **고장파형 4종 분류** — `src/api/mock.ts` `runAnalysis` |
| 한전 전력사용량 공공데이터 | 지역·시간대별 소비 패턴 | 패턴 분석·비교, 마을 부하 시나리오 (학습 미사용) |

IoT 이벤트를 사건으로 등록하면 DC 계측 기록 그대로 `IotCase`가 됩니다. 교류 파형으로 바꾸지 않습니다.

## 예시 데이터와 시나리오

- 처음 열면 **[예시] 사건 8건**이 실제와 같은 처리 과정(등록 → 진단 → 분석 → 검토)을 거쳐 만들어집니다: 분석·검토 완료, 판단 보류, 60Hz COMTRADE 범위 밖, 입력 거부, 원인 추정 요청 보류, IoT LED 단선(검토 완료)·전압 강하·릴레이 고착. 설정 → 사건 데이터에서 예시로 되돌리거나 모두 비울 수 있습니다 (`src/api/seed.ts`).
- 고장파형 등록 화면의 **예시 시나리오 15종** (`src/lib/scenarios.ts`): 1상 지락·순간 이상·2상/3상 단락·헤더 없음 / 샘플링·길이·60Hz 범위 밖 / 결측·채널 순서·빈 파일 / COMTRADE 60Hz·BINARY·In 없음·전압 채널 없음. 각 시나리오에 기대 판정이 붙어 있습니다.
- 스마트 마을 고장 시뮬레이션: LED 단선, 누설·과전류, 어댑터 전압 강하, 전원 상실, **릴레이 접점 고착**, **통신 끊김**.

## 목 데이터 주의

- 고장파형 분류 점수는 파일 해시로 만든 가짜 값입니다.
- 공공데이터 화면의 기본값은 **예시 데이터**(실제 한전 수치 아님)입니다. `CSV 양식 받기`로 형식을 확인하고,
  공공데이터포털·한전 전력데이터 개방포털에서 받은 CSV를 열 이름 `지역,계약종별,월,요일구분,시간,사용량`에 맞춰 가져오면 그 값으로 바뀝니다.
- 스마트 마을 계측값은 실측 장치를 연결하지 않으면 Mock 시뮬레이터 값입니다 (`arduino-sim-01`). 사이드바 하단에 출처가 표시됩니다.
- 공공데이터 패턴의 마을 재생은 시뮬레이터 전용입니다 (실제 회로에는 LED별 스위치가 없음).

## 실제 모형 연결 (선택)

회로는 최종 구성도 기준입니다.

```
5V DC 어댑터 → 1채널 릴레이 (Arduino D2, 마을 전체 ON/OFF) → INA219 VIN+ → VIN− → 브레드보드 1 (분배)
  → 브레드보드 2: 주택 1~3 (LED 1~3)   → 브레드보드 3: 가로등 1~2 (LED 4~5)     각 LED에 저항 직렬, LED끼리 병렬
INA219: A4(SDA) · A5(SCL) · 0x40
```

- 측정은 INA219 1개로 **마을 전체** 전압·전류만 합니다. LED별 상태는 전체 전류 ÷ LED 1개 정격(0.056 A)으로 켜진 개수만 추정하며, 어느 LED인지는 특정하지 않습니다.
- 제어는 릴레이 하나로 **마을 전체** 정전 발생 / 전력 복구만 할 수 있습니다.

Chrome·Edge에서 **설정 → 실측 장치**를 누르면 Web Serial로 모형과 통신합니다. 연결하지 않으면 Mock 시뮬레이터로 같은 화면이 동작합니다.
프로토콜(115200 baud, 줄 단위): 장치 → 웹 `{"v":5.02,"i":0.281,"relay":1}` (0.5초마다), 웹 → 장치 `RELAY 0` / `RELAY 1`.
부품·핀·배선 데이터는 `src/lib/hardware.ts` 한 곳에 있고, 3D 지하 배선과 설정의 배선표가 함께 씁니다. 배선 색은 도면의 색상 규칙(빨강 5V, 검정 GND, 초록 D2, 파랑 SDA, 노랑 SCL, 주황 LED+, 회색 LED−)을 따릅니다.
예제 스케치: `arduino/gridwitness_village/gridwitness_village.ino` (Adafruit INA219 라이브러리). 릴레이 모듈이 Active-Low면 스케치의 `RELAY_ACTIVE_LOW`를 바꿉니다.

## 3D 성능

기본 모드는 30fps·낮은 해상도·정적 그림자·후처리 없음으로 동작하고, 화면 밖이거나 탭이 숨겨지면 렌더링을 멈춥니다. 마을 화면의 **고화질** 버튼을 켜면 AO·블룸 후처리와 60fps를 씁니다.
